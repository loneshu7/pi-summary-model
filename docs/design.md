# Dedicated compaction model

Use a fixed user-selected model for all automatic and manual Pi compactions. The conversation model stays unchanged. This is ordinary model routing; errors never select another account/provider. Provider policy refusals stop the compaction.

Target Pi 0.86.0 and Node >=22. Implement a Pi TypeScript package named pi-summary-model with a single entry src/index.ts. Reuse Pi's exported compact() to preserve native summaries, split turns, previous summaries, custom instructions, recent message boundary, file metadata, and usage accounting. Route its stream calls through the current modelRegistry for configured provider authentication, including OAuth refresh. Check each response before accepting it, including blank text, error, abort, tool calls and length truncation.

Global config: getAgentDir()/summary-model.json. Store only provider and model IDs and enabled state, never credentials. Missing config is unconfigured and MUST cancel compaction with setup instructions rather than silently use the conversation model. Explicit /summary-model off allows default Pi compaction; /summary-model on requires valid saved config. /summary-model status prints route. /summary-model select offers available models (prefer openai-codex); /summary-model set <provider> <modelId> is usable without UI. Selection is global and takes effect at the next compaction; a running compaction captures its settings. Use atomic config writes and strict validation. No project-local overrides in v1.

Failures return {cancel:true}: throwing from the before hook alone is insufficient because Pi catches extension errors and can fall back. Report a bounded actionable error without logging raw provider responses or credentials. Esc must propagate to streaming. Do not retry or switch provider on failure. Missing models/auth must give actionable instructions. Manual /compact and threshold/overflow compaction use the same hook; /tree summarization is outside scope. Other compaction-providing extensions must be disabled to prevent last-wins hooks overriding successful output.

Tests must exercise real Pi compact() with deterministic fake modelRegistry streams, avoiding paid requests or user histories. Verify one fixed model, main model never changed, split turns/file tracking/previous summary/custom focus/usage, error/blank/truncated/aborted responses and hook cancellation, invalid config, credential absence, persistence and command setup. Check TypeScript and real Pi extension loading. Optional harmless synthetic live check uses official subscription only and does not include previous blocked content.

Publish source, tests, README, MIT license, and CI to a new private GitHub repository loneshu7/pi-summary-model; user authorized repository creation and push. No credentials, local config or conversation logs committed. Install local package after validation if it can be safely configured from existing subscription model metadata. Never trigger /reload from the running task.
